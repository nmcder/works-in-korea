## D-4. GitHub 레포는 프라이빗 (하이브리드)

**결정일** 2026-08-15 (운영자가 복제 우려 제기 후 재검토)
**결정** 측정 엔진은 프라이빗 레포. 산출 데이터와 웹사이트는 공개.

**검증 결과**
| 플랜 | 프라이빗 Actions 무료 시간 |
|---|---|
| **Free (기본 전제)** | **2,000분/월** |
| Pro (학생팩 승인 시) | 3,000분/월 |
| 퍼블릭 | 무제한 |

100개 서비스 일 1회 측정 ≈ 회당 20분 → **월 600분 추정**. **Free 플랜만으로 3배 여유.**
300개·일 3회로 늘려도 3,000분 안쪽(이 경우 Pro 필요).
학생팩은 보너스이지 전제 조건이 아님 — 승인 여부와 무관하게 진행.
Vercel Hobby는 프라이빗 레포와 연결 가능, Cloudflare Workers는 레포 무관.
→ **퍼블릭을 강제하는 요소가 없음.**

**근거**
- 코드는 해자가 아님. Playwright + Next.js 정적 사이트는 AI 도구로 일주일이면 재작성 가능
- 진짜 자산: ① 축적된 시계열(복제자는 스냅샷만 얻고 0일차부터 시작, 과거는 소급 생성 불가) ② 제보자 커뮤니티 ③ 인용 위치 ④ 도메인·백링크
- **데이터 공개는 엔진 공개와 무관.** 데이터가 열려야 AI가 인용하고 기관이 봄
- **순서가 중요**: 프라이빗→퍼블릭은 언제든 가능, 퍼블릭→프라이빗은 불가능. 되돌릴 수 없는 결정은 뒤로 미룸

**데이터 라이선스** CC BY (출처 표시 조건). 법적 집행보다 평판 보호 목적.

**재검토 시점** 시계열 자산이 6개월 이상 쌓인 뒤, 오픈소스 공개의 포트폴리오 이득과 비교.

## D-8. 측정할 수 없는 것은 측정하지 않는다 (1주차 구현 중 확정)

**결정일** 2026-08-15 (1주차 프로브 구현·검증 중)

명세(`02-product-spec.md` 4장)와 실제 측정 가능 범위가 어긋나는 지점이 3곳 나왔다.
전부 **추측으로 채우지 않고 측정 범위를 좁히는 쪽**으로 결정했다. 근거는 절대규칙 5.

### D-8-1. `app_availability` — 국가별 출시 여부는 측정하지 않는다

**검증 결과** 세 가지 공개 경로를 모두 시험했으나 어느 것도 배포 국가를 구분하지 못했다.

| 방법 | 결과 |
|---|---|
| `itunes.apple.com/lookup?country=XX` | 정부24·KB스타뱅킹도 us/de/jp에서 `resultCount=1` |
| `apps.apple.com/{cc}/app/id{id}` | 모든 국가 200 (없는 앱만 404) |
| `play.google.com/...&gl={cc}` | 모든 국가 200 (없는 패키지만 404) |

**결정** `countries` 는 항상 `null` 로 두고, 실제로 검증되는 **스토어 등재 여부**만 측정한다.
등재 여부 자체도 정보 가치가 있다(외국인이 앱 이름으로 못 찾는 경우가 흔하다).
부수 효과로 요청 수가 서비스당 28회 → 2회로 줄어 실행 시간이 크게 짧아졌다.

**재검토 시점** 국가별 측정 방법이 확인되면 `src/probes/app-availability.ts` 만 교체한다.

### D-8-2. `overseas_access` — 봇 차단과 지역 차단을 구분할 수 없으면 `unknown`

**문제** 쿠팡 등은 봇 User-Agent를 403으로 막는다. 이걸 "해외에서 차단됨"으로 발표하면
**사실이 아니고**, 기업 항의에 정당한 빌미를 준다 (리스크 표의 "우리 사이트를 그렇게 표시하지 말라" 항목).

**결정** `blocked` 로 단정하는 조건을 좁혔다.
- `blocked`: 본문이 지역·국가 제한을 **명시**하거나 HTTP 451
- `unknown`: 403/429, 또는 "Access Denied" 류의 사유 불명 거부 → 근거를 evidence에 남기고 판정 보류
- `ok`: 2xx/3xx 정상 응답 / `degraded`: 5xx

봇 차단 여부는 실제 브라우저 접속 제보로만 확정 가능하므로 커뮤니티 제보 항목으로 넘긴다.

### D-8-3. 차단·오류 페이지를 측정 근거로 쓰지 않는다

`i18n_ui` 와 `payment_gate` 가 403 차단 페이지를 그대로 분석해
"이 서비스는 한국어만 제공", "PG 없음" 같은 **틀린 값**을 만들어내고 있었다.
두 프로브 모두 2xx/3xx 응답을 받았을 때만 측정하도록 고쳤다. 아니면 `unknown`.

## D-9. robots.txt가 자동 측정의 상한이다 (1주차 실측)

**실측** 시드 106개 중 **28건(26%)이 자동 측정 불가**였다.

| 사유 | 건수 | 예 |
|---|---|---|
| robots.txt `Disallow: /` | 약 22건 | 네이버쇼핑·네이버예약, 카카오선물하기·카카오뱅크, 인터파크, 무신사, 멜론, 11번가, 롯데온 |
| 봇 UA를 403으로 차단 | 약 7건 | 쿠팡, G마켓, 옥션, CGV, 올리브영 |

검증해 보니 이 사이트들은 Googlebot·Applebot 등 **지정 봇만 화이트리스트**로 허용하고
`User-agent: *` 에는 전면 금지를 건다. 우리 봇은 정확히 그 대상이다.

**결정** robots.txt를 우회하지 않는다. 크롤링 정당성 유지가 프로젝트 생존 조건이므로(D-6),
이 26%는 **커뮤니티 제보로만 채우는 영역**으로 확정한다.

**함의 (제품 설계에 반영할 것)**
- 3주차 제보 레이어는 "봇이 못 하는 것을 보완"이 아니라 **주요 서비스 상당수의 유일한 데이터원**이다.
  우선순위를 높게 볼 것.
- 사이트에 "이 서비스는 robots.txt로 자동 측정을 금지하고 있어 제보로만 채웁니다"를 명시한다.
  이것 자체가 정직성의 근거이자 제보 유도 장치다.

## D-10. 가입 본인인증 판정 — "무엇을 봤는지"까지 확인한 뒤에만 값을 낸다

**결정일** 2026-08-15 (운영자가 1등급 33건의 가입 주소를 제공한 직후, 실측 검증 중)

운영자가 채워 준 주소로 처음 측정했을 때 **양방향 오류가 실제로 발생**했다.

| 사례 | 잘못된 결과 | 원인 |
|---|---|---|
| KT `accounts.kt.com/identify/personal` | `not_required` | 페이지에 "본인확인… 주민등록번호 앞 7자리… PASS 또는 아이핀으로 인증하기"가 그대로 있는데, 시그니처 사전에 `본인확인`·`아이핀`·`인증번호`가 없어 못 잡음 |
| 신한은행 회원가입**안내** 페이지 | `not_required` → (사전 보강 후) `required` | 입력 양식이 아니라 안내 문서였다. 위젯이 없는 게 당연한데 "불필요"로 발표할 뻔했고, 반대로 안내문의 "주민등록번호" 언급만으로 "필수"로 발표할 뻔했다 |
| 쿠팡 `login.coupang.com` | `not_required` | 가입이 아니라 로그인 화면이었다 |

**결정** 값을 내기 전에 두 가지를 함께 확인한다.

1. **페이지 종류** (`src/lib/page-kind.ts`) — 가입 관련 표시가 없고 로그인 표시만 있으면 판정하지 않는다.
   로그인 절차를 재고 가입이라고 발표하면 잰 것과 발표한 것이 달라진다.
2. **입력 양식 존재** — 사람이 채우는 입력칸이 2개 이상 있어야 한다.
   - 입력칸 없음 → `unknown` ("안내 페이지로 보임")
   - 입력칸 있음 + 시그니처 없음 → `not_required`
   - URL 시그니처 탐지, 또는 텍스트 시그니처 + 입력 양식 → `required` / `optional`

즉 **텍스트 문구만으로는 required 를 발표하지 않는다.** 위젯 URL이 잡히거나,
문구와 실제 입력 양식이 함께 있어야 한다. evidence에 `page_kind`와 `form_input_count`를 남겨
왜 그렇게 판정했는지 외부에서 반증할 수 있게 한다.

**부수 결정** 시그니처 사전에 `본인확인`, `아이핀/i-PIN`, `인증번호 받기`, `주민등록번호`,
`외국인등록번호` 등을 추가했다 (`data/signatures/identity-verification.json`).
`주민등록번호` 요구는 외국인에게 특히 중요한 신호라 별도 항목으로 분리했다.

**알려진 한계** 해시 라우팅 기반 SPA(예: 신한은행)는 실행 시점에 따라 렌더링 결과가 달라져
값이 흔들릴 수 있다. `/changes` 에 가짜 변경으로 잡힐 여지가 있으므로, 2주차에
"연속 2회 같은 값일 때만 변경으로 인정" 같은 안정화 장치를 검토할 것.
