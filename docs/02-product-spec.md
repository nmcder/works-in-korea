# 제품 명세

---

## 1. 한 줄 정의

한국 온라인 서비스가 외국인에게 실제로 작동하는지를 **매일 자동 측정**하고, **측정 시각·방법·신뢰도와 함께** 공개하는 열린 데이터베이스.

## 2. 핵심 원칙

1. **모르면 "모름"이라고 쓴다.** 추측으로 칸을 채우는 순간 제품의 유일한 자산이 사라집니다.
2. **평가하지 않고 사실만 기술한다.** 등급·점수·순위보다 "무엇이 언제 어떻게 측정됐는가"가 우선입니다.
3. **모든 값은 반증 가능해야 한다.** 각 값에 측정 방법과 원본 근거(응답 코드, 탐지된 셀렉터 등)를 남깁니다.
4. **결제와 로그인은 자동으로 시도하지 않는다.** 이 두 영역은 커뮤니티 제보로만 채웁니다.

## 3. 데이터 모델

서비스 1개 = JSON 파일 1개 (`data/services/<id>.json`). git에 커밋되므로 변경 이력이 자동 축적됩니다.

```jsonc
{
  "id": "coupang",
  "name": { "en": "Coupang", "ko": "쿠팡" },
  "url": "https://www.coupang.com",
  "category": "shopping",        // shopping | transport | ticketing | delivery | finance
                                 // | telecom | government | healthcare | accommodation | culture
  "importance": 1,               // 1(필수)~3(선택) — 외국인 방문자 기준 우선순위
  "signals": {
    "<signal_key>": {
      "value": "ok",             // 시그널별 열거값. 아래 4장 참조
      "measured_at": "2026-08-15T03:00:00Z",
      "method": "auto:multi-region-probe",   // auto:* | community | manual
      "confidence": "auto",      // auto | community | conflicting | unknown
      "evidence": {              // 반증 가능하게 남기는 원본 근거
        "http_status": 200,
        "regions": { "us": 200, "jp": 200, "eu": 403 },
        "note": null
      },
      "history_ref": "git"       // 이력은 git log로 추적
    }
  },
  "notes": {                     // 사람이 쓰는 짧은 보충. 선택 사항
    "en": "English checkout exists at a separate subdomain.",
    "ko": null
  }
}
```

**`confidence` 정의**

| 값 | 의미 |
|---|---|
| `auto` | 봇이 직접 측정. 재현 가능 |
| `community` | 제보 기반. 봇이 측정할 수 없는 항목(결제·SMS) |
| `conflicting` | 제보들이 서로 엇갈림 → UI에 "엇갈림"으로 노출하고 추가 제보 요청 |
| `unknown` | 측정 실패 또는 미측정. **비워두지 말고 명시적으로 unknown** |

## 4. 자동 측정 시그널 6종 (사람 개입 0)

| # | 키 | 측정 내용 | 방법 | 열거값 |
|---|---|---|---|---|
| 1 | `overseas_access` | 해외 IP에서 접속되나 | GitHub Actions 러너(해외)에서 상태코드 + 본문 해시 확인. 다지역 확장은 `vantage_points` 배열로 열려 있음 | `ok` / `blocked` / `degraded` / `unknown`. 봇 차단과 지역 차단을 구분 못 하면 `unknown` → D-8-2 |
| 2 | `i18n_ui` | 영·중·일 UI가 실제로 있나 | `Accept-Language` 변조 후 렌더링 diff + `hreflang` + `/en` 류 경로 탐지 | 제공 언어 배열 + 번역 커버리지 추정치 |
| 3 | `signup_phone_auth` | 가입에 한국 휴대폰 본인인증이 강제인가 | 가입 페이지 DOM에서 PASS·NICE·KCB 위젯 시그니처 탐지 (**가입 시도는 안 함**) | `required` / `optional` / `not_required` / `unknown` |
| 4 | `app_availability` | 앱이 스토어에 등재돼 있나 | App Store / Google Play 조회 | 등재 여부 (iOS·Android). **국가별 출시 여부는 측정 불가로 확인됨 → D-8-1** |
| 5 | `payment_gate` | 결제 게이트가 어떤 형태인가 | 결제 페이지 PG사(이니시스·토스페이먼츠·KG 등)·3DS 시그니처 탐지 (**결제 시도 안 함**) | PG 목록 + 3DS 요구 여부 |
| 6 | `support_en` | 영문 고객지원 채널이 있나 | 페이지 텍스트를 LLM으로 분류 | `yes` / `no` / `unknown` |

**7. 변경 감지** — 위 전부의 일간 diff. "이 항목은 3일 전 바뀜"을 UI에 표시. git log에서 자동 도출됩니다.

### 자동 측정 시 금지 사항 (재확인)

- 계정 생성·로그인 시도 ❌
- 결제 시도 ❌
- robots.txt 무시 ❌
- 고빈도 요청 ❌ (기본 하루 1회)
- User-Agent에 프로젝트 URL·연락처 미기재 ❌

## 5. 커뮤니티 제보 시그널 (봇이 못 하는 것)

| 키 | 내용 | 수집 항목 |
|---|---|---|
| `foreign_card` | 해외 발급 카드 실결제 성공 여부 | 카드 브랜드, 발급 국가, 성공/실패, 실패 메시지, 시도 일자 |
| `foreign_phone_sms` | 해외 번호로 SMS 인증 수신 성공 여부 | 국가번호, 통신사, 성공/실패, 시도 일자 |

**수집 방식: GitHub Issue Form**
- 백엔드·DB·스팸필터를 GitHub에 위임 → 서버 0대
- **개인정보 수집 0** (이름·이메일·전화번호 받지 않음. 카드 브랜드와 발급국만)
- LLM이 제보를 정규화하고 기존 데이터와의 모순을 판정 → 운영자는 승인만
- 제보가 엇갈리면 `confidence: conflicting` 으로 표시하고 추가 제보를 요청 (은폐하지 않음)

## 7. 사이트 구조

- `/` — 검색 + 필터 (카테고리, 시그널별, "최근 변경됨")
- `/service/<id>` — 서비스 상세. 각 시그널의 값·측정시각·방법·근거·변경 이력
- `/changes` — 최근 변경 타임라인 (git log 기반). **재방문 유도의 핵심 페이지**
- `/api/*` — 정적 JSON. 전체 덤프 + 서비스별. CC BY
- `/method` — 측정 방법 전면 공개. 정정 요청 채널 상단 배치
- 언어: 영어 우선(주 사용자), 한국어 병기

**로그인 없음. 개인정보 수집 없음. 광고 없음. 후원 버튼 없음.**

## 8. 배포 전략 (제로클릭 시대 대응)

SEO에 의존하면 안 됩니다(정보성 질의 제로클릭 74%).

1. **커뮤니티 직접 배포** — r/korea, r/Living_in_Korea, r/koreatravel, Hacker News

3. **언론** — 관광 불만 3년 새 6배는 그 자체로 기사 소재
